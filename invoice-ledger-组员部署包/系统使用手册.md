# 链证项目管理与发票报销系统使用手册

> 若需要把项目交给未参与开发的组员独立部署，请优先发送 [组员部署与快速上手手册.md](组员部署与快速上手手册.md)。该版本包含环境安装、首次部署、重启恢复、完整演示流程与常见故障排查。

本手册面向项目组成员和演示使用者。即使没有参与开发，也可以按本文完成环境启动、组织登记、注册、项目申请、发票存证、报销、作废申请和核验。系统运行在 Hyperledger Fabric 测试网络上；页面中标记为“已写入链上”的业务记录可追溯、不可直接修改或删除。

## 1. 使用前准备

### 1.1 你需要具备什么

- Ubuntu、WSL 或虚拟机环境；
- Docker 与 Docker Compose 已安装，并且当前用户可执行 `docker ps`；
- Go 已安装；
- 完整项目目录，以及项目内的 `fabric-runtime/` 运行环境目录。

> `fabric-runtime/` 中包含 Fabric 二进制、配置和 Test Network。它体积较大，因此不会上传到 GitHub。新电脑首次部署时应使用**未初始化的运行环境模板**；不要直接复制已运行网络产生的证书与通道材料。模板打包、解压和部署步骤见 [组员部署与快速上手手册.md](组员部署与快速上手手册.md)。

OCR 是可选能力。未配置阿里云密钥时，系统仍可手动录入发票，不影响项目、报销和区块链功能。

### 1.2 第一次启动或已重置网络

系统管理员先在项目根目录检查环境，再按“首次初始化”或“恢复运行”选择操作：

```bash
cd /home/wenqin/bc/blockchain/project/invoice-ledger
./scripts/start-network.sh check  # 检查 Docker、Fabric 二进制与 .env 路径
./scripts/start-network.sh init   # 仅首次：创建网络和 mychannel
./scripts/deploy-chaincode.sh     # 仅首次：部署链码
./scripts/start-app.sh
```

浏览器访问：`http://localhost:8080`。

看到链码部署输出中的 `Chaincode definition committed` 后，再执行 `start-app.sh`。终端显示“链证发票服务已启动”即表示可打开浏览器。

### 1.3 恢复运行、更新代码与链码升级

- 电脑重启后，先执行 `./scripts/start-network.sh resume` 恢复已有容器，再执行 `./scripts/start-app.sh`。`resume` 不会创建或重复加入通道。
- 若 Docker 容器仍在运行，通常只需执行 `./scripts/start-app.sh`。
- 修改了前端页面后，浏览器按 `Ctrl + F5` 强制刷新；修改 Go 后端后，先在后端终端按 `Ctrl + C`，再重新执行 `./scripts/start-app.sh`。
- 从刚完成首次部署的 v2.4 / Sequence 1 更新到本版时，先执行：

```bash
./scripts/upgrade-chaincode-v2.6.sh
./scripts/start-app.sh
```

该升级会保留现有账本数据，并增加 Org2 组织管理员引导身份与“取消发票项目关联”操作；不要对已经部署过链码的网络重复执行 `deploy-chaincode.sh`。若已运行过 v2.5 升级、当前为 Sequence 2，则执行 `./scripts/upgrade-chaincode-v2.6.sh 2`；其他 Sequence 请先向维护者确认，不要猜测数字。

若页面提示连接 `127.0.0.1:7051` 被拒绝，说明 Fabric 网络没有启动，应执行 `./scripts/start-network.sh resume`，不要误用 `init`。

## 2. 页面与基本规则

登录后，可使用左侧边栏切换功能：

| 页面 | 用途 |
| --- | --- |
| 工作概览 | 查看发票数量、流转中数量、总金额和当前登录身份。 |
| 组织管理 | 登记牵头单位、内部项目组和外部协作组织；点击组织可查看其链上成员。 |
| 项目管理 | 项目申请、立项审核、结项审核和资金池查看。 |
| 发票存证 | OCR 识别或手工录入发票，并将其存证到链上。 |
| 发票账本 | 搜索发票、查看详情、流转轨迹、作废记录和历史。 |
| 报销支付 | 用项目中的已存证发票创建报销单、审核及确认支付。 |
| 数据统计 | 查看项目资金池汇总、近 7 天报销申请、近 6 个月实际支付和报销单状态分布。 |
| 发票核验 | 按发票票面填写关键内容，由系统重算摘要并验证是否与链上记录一致。 |

系统会自动生成项目 ID、报销单 ID 和发票 ID 等内部编号，普通使用者无需填写或记忆；发票号码仍应填写真实、唯一的发票号码。

> 注意：页面上的“作废”不会删除链上数据，而是新增一条作废交易。因此，已作废发票仍可在账本和历史中查询，但不能用于报销。

## 3. 注册、登录与岗位

### 3.1 新用户注册

1. 在登录窗口点击“没有业务账户？去注册”。
2. 填写登录账号、姓名或主体名称，从下拉框选择已登记的业务组织并设置密码。
3. 登录账号只能使用 3–32 位英文、数字、下划线或连字符；密码至少 6 位。
4. 点击“注册并写入区块链”。

注册成功后：姓名、账号、所属业务组织和“项目组成员”岗位会写入 Fabric 成员名录；密码只以哈希形式保存在本机的 `backend/data/accounts.json`，不会写到区块链上。审核、财务、组织管理等高权限岗位不能自助注册，仍使用演示账号或由后续的组织管理员配置流程授予。

本课程测试网络中，系统按所选组织使用其代表性的 Fabric 测试证书提交交易；“注册业务用户”创建的是系统内的链上业务档案，并不等同于为每位用户单独签发新的 X.509 证书。

### 3.3 各岗位可以做什么

| 岗位 | 主要操作 |
| --- | --- |
| 项目组成员 | 创建、修改和提交项目；申请结项；存证关联本项目的发票；提交报销单；申请作废本人项目关联的发票。 |
| 项目管理审核员 | 审核项目立项、结项和报销单，并填写审核意见。 |
| 财务管理员 | 对已审核并冻结额度的报销单确认支付。 |
| 开票员 | 创建发票、创建项目、提交报销；可直接作废本组织开具的发票，并审核项目组的作废申请。 |
| 跨组织流转员 | 在确有组织间交接需要时接收或继续流转发票。 |
| 审计员 | 查询成员、项目、发票、流转历史和核验结果。 |

页面会按岗位隐藏无权限的按钮；即使通过接口直接请求，后端和链码也会再次校验权限。

### 3.4 登记业务组织

“组织管理员”可在“组织管理”页面登记三类业务组织：牵头单位（学校/总部）、公司内部项目组、外部协作组织（财务或合作单位）。内部项目组必须选择一个已登记的牵头单位作为上级组织。打开牵头单位时，成员名录会汇总显示直属成员及其下属项目组成员，并标注每位成员的实际归属。

第一次使用可按以下顺序操作：

1. 使用内置账号 `org-admin / orgadmin123` 登录，可登记接入 `Org1MSP` 的业务组织。
2. 登记一个“牵头单位”，例如“某某大学”或“公司总部”。
3. 登记“内部项目组”时，选择刚创建的牵头单位作为上级组织。
4. 如需把外部协作组织登记到 `Org2MSP`，退出后使用 `org-admin-org2 / orgadmin234` 登录，再登记该外部组织；若只是业务分类，外部组织也可由 Org1 管理员登记在 Org1 节点。
5. 普通成员注册时选择对应的业务组织；系统默认授予“项目组成员”岗位。

这里登记的是业务组织档案，会写入 Fabric 账本；它不会自动创建新的 Fabric Peer、MSP 或区块链证书。当前课程网络底层仍使用 Org1MSP 与 Org2MSP 两个技术节点。详细区别见 [组织管理说明.md](组织管理说明.md)。

## 4. 推荐的完整业务流程

推荐按以下顺序演示或日常使用：

```text
项目组成员创建项目
  → 提交立项申请
  → 项目管理审核员通过
  → 项目进入执行中（未拨款），开展项目工作并准备验收材料
  → 结项验收通过，项目进入财务结算并获得可用额度
  → 项目成员存证关联项目的发票
  → 提交报销单
  → 审核员通过并冻结相应额度
  → 财务管理员确认支付
  → 资金池的已支付金额增加
  → 处理完待审单据后归档，回收剩余额度
```

立项通过后项目进入“执行中（未拨款）”，用于完成项目工作和准备结项材料；此时不能报销。结项验收通过后，预算才进入“财务结算中”，项目成员可提交尾款报销。全部待审报销处理完、冻结额度清零后，财务管理员点击“完成结算并归档”，系统回收剩余额度，归档项目不能再新增发票或报销。

## 5. 项目管理

### 5.1 创建并提交项目

1. 使用“项目组成员”或“开票员”账号登录，进入“项目管理”。
2. 填写项目名称、项目内容、预期结项日期和申请预算，点击“保存项目草稿”。
3. 在项目列表找到该项目，点击“提交”。
4. 项目状态变为“待立项审核”。

草稿或被要求修改的项目可以由原申请人编辑后再次提交。项目 ID 由系统自动生成，不需要手工填写。

### 5.2 审核立项和结项

1. 使用“项目管理审核员”登录。
2. 在待审核项目所在行点击“立项审核”，或点击“详情”后在详情底部操作。
3. 填写具体审核意见，选择“通过立项”或“要求修改”。
4. 通过后项目进入“执行中（未拨款）”。项目工作可以开展，但预算尚未成为可报销额度；结项验收通过后，项目才进入“财务结算中”并获得可用额度。

项目负责人在项目“执行中”时可点击“申请结项”，填写结项报告、成果材料或链接说明。审核员按同样方式进行结项审核。负责人可在项目详情的“项目成员”区域添加同组织已注册成员；成员可为项目关联发票、提交报销和申请作废，但不能替代负责人修改申请或提交结项。

### 5.3 查看资金池

项目列表和详情会显示三项金额：

- 可用余额：尚未被报销审核占用的额度；
- 冻结额度：报销已审核通过、等待财务支付的额度；
- 已支付：财务已确认支付的总额。

系统不允许审核通过后使“可用余额”小于零。

## 6. 发票存证与 OCR

### 6.1 使用 OCR 识别

1. 进入“发票存证”。
2. 点击“选择发票文件”，或直接将图片/PDF 拖入虚线区域。
3. 点击“开始识别”。识别成功后会回填发票号码、日期、销售方、购买方和金额等字段。
4. 人工检查和补全所有字段后，再点击“生成存证并上链”。

OCR 仅用于辅助录入；识别结果不会自动上链。请特别核对金额、税额、日期、发票号码和关联项目。若未配置阿里云 OCR，仍可完全手工填写发票信息。

### 6.2 手工存证

填写发票号码、开票日期、销售方、购买方、金额和税额，必要时从“关联项目”选择处于财务结算阶段的项目。当前课程版本的项目资金池统一以人民币（CNY）核算，不接受美元等其他币种。提交后系统会自动：

1. 生成发票 ID；
2. 根据规范化的发票字段计算 SHA-256 内容摘要；
3. 将发票、指纹、当前责任人及首次存证记录写入 Fabric。

相同发票 ID 或相同发票号码不能重复存证。若原存证因录入错误已作废，可在详情中创建“更正版本”：原记录仍保留，更正版本沿用相同票号并建立更正关系。未关联项目、未作废且未报销的发票，也可在详情中补关联项目。

### 6.3 发票详情、作废与跨组织流转

在“发票账本”中，可按发票 ID、发票号码、销售方、购买方或当前责任人搜索。点击“详情”可查看：发票字段、流转轨迹、作废申请与链上操作记录；如有审计需要，可手动展开交易编码。

- **直接作废/红冲**：开票员只能直接作废本组织开具、且未作废、未关联任何报销单的发票。若已提交报销，应先完成报销单的退回、撤销或结算处理，不能出现“已作废仍付款”的矛盾状态。
- **材料交接**：这是可选操作，普通项目报销不需要它。当前责任人发起交接申请并填写说明；接收人可确认或拒绝，只有确认后责任人才会变更。发起人可在接收前撤回申请；接收人可以是具备相应业务权限的项目成员、开票员或流转员。

### 6.4 项目组申请作废

适用场景：项目成员发现已关联本人项目的发票录入有误、需要重新开具，但没有直接作废权限。

1. 使用该项目的申请人（项目组成员）登录，在“发票账本”打开目标发票的“详情”。
2. 在“项目组作废申请”区域填写具体原因，点击“提交作废申请”。
3. 此时发票**不会立即作废**，状态为等待开票员审核；申请记录已写入链上。
4. 使用该发票发行组织的“开票员”登录，打开同一张发票详情。
5. 查看申请人、原因和时间，填写审核意见，选择“批准并正式作废”或“驳回申请”。
6. 批准后，发票状态变为“已作废”，无法再用于报销；驳回后发票保持有效，项目成员可补充原因并再次提交。

发票详情的“发票流转”会按时间显示开具、提交申请、驳回和最终作废等链上记录。

## 7. 报销与支付

### 7.1 提交报销单

1. 使用项目申请人（项目组成员或开票员）登录，进入“报销支付”。
2. 先选择执行中的关联项目。
3. 系统只会列出该项目下、未作废且尚未用于报销的发票；选择一张发票。
4. 填写材料说明，例如支付凭证、采购用途或附件位置。
5. 点击“提交报销审核”。

报销单 ID 会自动生成。金额取自所选发票，不能在报销单中任意修改。

若审核员选择“要求修改”，申请人可在该报销单的“详情”中查看材料说明与审核意见，补充或修改材料后点击“重新提交审核”。系统会保留新旧材料版本的链上记录。若不再报销，可在详情中“撤回”：待审核/退回状态会解除发票占用；已冻结但未支付的状态还会自动释放额度。已支付报销单不可撤回。

### 7.2 审核与支付

1. 项目管理审核员登录，在待审核报销单右侧点击“审核”。
2. 选择通过或要求修改，并填写审核意见。
3. 审核通过后，报销单状态变为“已审核，额度已冻结”。
4. 财务管理员登录，对该报销单点击“确认支付”。
5. 支付确认后状态变为“已支付”，冻结额度转入已支付金额。

## 8. 发票核验

核验用于确认一张待核验发票的票面关键内容是否对应链上存证。它不会把链上摘要自动填入页面，因此不是“复制后比对”的形式核验。

1. 在“发票账本”打开目标发票的“详情”。
2. 点击“前往核验中心”，系统只会带入发票 ID。
3. 参照待核验的真实票面，填写发票号码、日期、销售方、购买方、购买方关联组织、金额和税额，然后点击“核验票面内容”。

显示“核验通过”代表系统重算后的票面内容摘要与链上记录一致，且该票当前有效。若任一关键字段不一致，系统会提示核验未通过；若内容一致但该票已作废，系统会明确提示不能继续用于报销。

## 9. 常见问题

### 页面提示未登录或登录后没有权限

先确认账号密码是否正确，再查看左下角显示的姓名、组织和岗位。需要其他操作时，请退出并登录对应岗位的账号；不要尝试借用他人的密码。

### 提示“连接被拒绝”或“区块链交易未提交”

通常是 Fabric 网络未运行、链码未部署或刚重启尚未就绪。由管理员先运行 `./scripts/start-network.sh check`，已有网络使用 `./scripts/start-network.sh resume`；只有全新网络才使用 `init` 和 `deploy-chaincode.sh`。已存在网络时不要反复部署同一序列号链码。

### 发票或项目没有出现在下拉框

点击相应页面右上角“刷新”。报销区只显示“当前项目关联、未作废、未被其他报销单使用”的发票；项目下拉框只显示可报销状态的项目。

### 看不到“项目组作废申请”或提交后提示接口不存在

确认已升级到本版链码并重启后端。对于 v2.1 / Sequence 3 的旧网络，在项目根目录执行：

```bash
./scripts/upgrade-chaincode-v2.4.sh
./scripts/start-app.sh
```

此外，项目组成员只能对“自己申请的项目”关联发票提出申请；未关联项目的发票只能由开票员直接作废。

### OCR 识别失败

确认文件为清晰的图片或 PDF、文件大小未超过限制，并检查管理员是否已在项目 `.env` 中配置阿里云 OCR 的 AccessKey。OCR 输出只能作为录入建议，应以原始发票为准。

### 重启后自己注册的账号无法登录

检查 `backend/data/accounts.json` 是否被删除或替换。该文件保存本机的密码哈希；系统每次写入会保留上一份 `accounts.json.bak`，主文件损坏时会自动从备份恢复；主备都损坏时服务会拒绝启动，避免悄悄丢失登录账户。删除它会清除本机登录凭据，但不会自动删除链上的业务用户档案。

## 10. 安全提示

- 不要把 `.env`、阿里云 AccessKey、密码或 `backend/data/accounts.json` 提交到 GitHub。
- 不要为了“重新测试”直接删除单条链上发票；应使用作废功能，保留可审计记录。
- 项目成员提交的作废申请并不会立即删除或作废发票，必须由开票员审核后才会改变发票状态。
- 课程测试网络仅用于开发演示，不能直接作为生产财务系统使用。
