# 链证项目管理与发票报销系统：录屏演示完整脚本

> 建议最终视频控制在 6 分 30 秒至 7 分钟。不要强求一次录完，可以按章节分别录制，再剪掉登录等待、页面加载和输入文字的停顿。录屏期间不要展示 `.env`、AccessKey 或终端中的敏感配置。

## 一、录屏目标

这段视频需要让没有参与开发的老师和同学在较短时间内看懂四件事：

1. 系统解决了什么问题；
2. 项目、发票、报销和支付如何形成完整业务闭环；
3. Hyperledger Fabric 在系统中具体承担什么作用；
4. 系统相比普通发票登记页面有什么特色。

推荐突出以下能力：

- 多组织、分岗位协作；
- 项目立项、结项、额度发放和财务归档；
- 阿里云 OCR 自动识别发票并人工确认；
- 发票存证、报销审核、额度冻结和支付；
- 作废申请与开票方审核；
- 跨组织票据材料交接确认；
- 链上操作轨迹、交易编码和统计分析。

## 三、7 分钟主视频脚本

## 00:00—00:30 开场：应用场景与系统定位

### 画面操作

1. 打开系统登录页或工作概览页。
2. 缓慢展示系统标题和左侧菜单。

### 解说词

> 大家好，我们的作品是“链证项目管理与发票报销系统”。系统面向学校、企业总部、内部项目组以及外部财务协作机构，解决项目审批、发票登记、报销审核和支付过程分散，票据状态难以追溯、跨组织信息难以互信的问题。系统采用 B/S 架构，前端通过浏览器使用，后端由 Go 和 Gin 实现，核心业务账本与智能合约运行在 Hyperledger Fabric 上，并接入阿里云 OCR 辅助录入发票。

## 00:30—01:05 身份、组织和预置业务概览

### 画面操作

1. 使用 `alice / alice123` 登录。
2. 在工作概览停留，指出当前登录人和岗位。
3. 打开“组织管理”。
4. 展示“浙江大学”“区块链技术实践项目组”“校外财务协作中心”。
5. 点击项目组的成员按钮，展示 Alice 和 Bob。

### 解说词

> 系统采用基于岗位的权限控制。当前登录的是项目成员 Alice，页面会显示她的姓名、所属组织和岗位。链上组织目录中包含牵头单位、内部项目组和外部协作组织，各业务组织绑定 Org1 或 Org2 的 Fabric 接入节点。点击组织还能查看链上登记的成员。不同岗位只能看到并操作自己权限范围内的数据，审计员则可以进行全局查询。

## 01:05—02:25 项目申请、成员协作、立项与结项

### Alice 的画面操作

1. 进入“项目管理”。
2. 创建新项目：

```text
项目名称：区块链发票管理系统建设项目
项目内容：开发基于 Hyperledger Fabric 的项目管理、发票存证、流转核验和报销支付系统。
项目预算：10000
预计结项日期：2026-12-31
```

3. 点击“保存项目草稿”。
4. 在项目列表中点击“详情”，在成员区域添加 `bob`。
5. 关闭详情并点击“提交”，提交立项审核。

### 解说词

> 项目成员首先创建项目申请，填写项目目标、预算和预计结项日期。项目 ID 由系统自动生成，不需要人工编写。项目负责人还可以从同一组织的已注册成员中添加协作者。保存草稿后提交立项，项目状态和操作事件会写入 Fabric 账本，后续不能直接删除历史。

### 审核员的画面操作

1. 退出 Alice，登录 `project-reviewer / review123`。
2. 进入“项目管理”，找到刚创建的项目。
3. 点击“立项审核”或“详情”。
4. 输入：

```text
项目目标明确，技术路线合理，预算符合课程实践要求，同意立项。
```

5. 点击“通过立项”。

### 解说词

> 项目管理审核员可以在详情中同时查看申请内容、成员和历史，再填写审核意见。立项通过后，项目进入执行中，但此时还没有获得可报销额度，这样可以避免项目刚申请就直接使用资金。

### Alice 申请结项

1. 退出并重新登录 Alice。
2. 打开该项目，点击“申请结项”。
3. 输入：

```text
项目功能开发和实验验证已经完成，已提交系统源码、测试记录和项目说明材料。
```

4. 提交结项申请。

### 审核员完成结项

1. 切换至 `project-reviewer`。
2. 打开项目的结项审核。
3. 输入：

```text
系统功能和实验材料完整，同意通过验收并进入财务结算。
```

4. 点击通过。

### 解说词

> 项目完成后由负责人申请结项。审核员确认成果后，项目才进入财务结算阶段，并按照申请预算获得一万元可用额度。系统把“项目工作验收”和“财务结算归档”分开，验收后可以处理尾款，最后再回收未使用额度。

## 02:25—03:25 OCR 发票识别与链上存证

### 画面操作

1. 切换回 Alice。
2. 进入“发票存证”。
3. 将下面文件拖入 OCR 区域：

```text
发票/_26442000009787747261.pdf
```

4. 点击“开始识别”。
5. 展示识别结果和自动回填字段。
6. 人工快速核对以下信息：

```text
发票号码：26442000009787747261
销售方：广州市星翼电子科技有限公司
购买方：浙江大学
开票日期：2026-08-26
不含税金额：246.90
税额：32.10
价税合计：279.00
```

7. “关联项目”选择刚创建的“区块链发票管理系统建设项目”。
8. 点击“生成存证并上链”。
9. 等待成功提示后进入“发票账本”，搜索该发票号码。

### 解说词

> 发票可以手工填写，也可以直接拖拽图片或 PDF。这里调用阿里云统一 OCR 自动识别票号、购销双方、日期和金额，再由用户人工确认，系统不会让 OCR 结果未经检查就直接上链。提交时，后端会规范化关键字段并计算 SHA-256 内容摘要，智能合约同时检查票号是否重复、项目和组织是否匹配。原始 PDF 不直接写入区块链，链上保存关键业务字段、内容指纹、状态和后续操作轨迹，从而兼顾可追溯性与存储效率。

## 03:25—04:35 报销申请、审核、额度冻结和支付

### Alice 的画面操作

1. 进入“报销支付”。
2. 选择“区块链发票管理系统建设项目”。
3. 选择刚存证的 ¥279.00 发票。
4. 点击发票“详情”，短暂停留展示票面信息。
5. 材料说明填写：

```text
项目开发所需电子设备采购，发票与支付凭证已经核对。
```

6. 点击“提交报销审核”。

### 解说词

> 创建报销单时，用户先选项目，再从系统筛选出的可用发票中选择，不需要记忆发票 ID。系统自动读取发票金额，并检查发票是否有效、是否属于当前项目、是否已被其他报销单占用，以及项目额度是否足够。报销单 ID 同样由系统自动生成。

### 审核员的画面操作

1. 切换至 `project-reviewer`。
2. 进入“报销支付”，找到 ¥279.00 待审核记录。
3. 打开审核详情，展示关联项目、发票和材料说明。
4. 输入：

```text
发票信息、采购用途和项目材料一致，同意报销。
```

5. 点击审核通过。

### 解说词

> 审核员在同一个详情窗口中查看报销单、关联项目和发票，再填写审核意见。审核通过后，279 元从项目可用额度转为冻结额度，避免同一笔预算被重复占用，但此时还没有记为实际支付。

### 财务管理员的画面操作

1. 切换至 `finance-admin / finance123`。
2. 打开同一张报销单。
3. 点击“确认支付”。
4. 再打开项目详情，展示“冻结额度归零、已支付增加”。
5. 如果时间充足，点击“完成结算并归档”，展示剩余额度被回收。

### 解说词

> 财务管理员确认付款后，冻结额度转为实际已支付金额。所有待处理报销完成后，可以进行最终结算归档，系统会回收项目剩余额度，并阻止归档项目继续新增发票或报销。这形成了预算、冻结、支付和回收的完整资金闭环。

## 04:35—05:15 发票作废申请与审核

### Alice 的画面操作

1. 切换回 Alice。
2. 进入“发票账本”。
3. 搜索：

```text
26332000007324083826
```

### 开票员的画面操作

1. 切换至 `issuer-org1 / issuer123`。
2. 搜索同一发票并打开详情。
3. 填写：

```text

```

4. 点击“批准并正式作废”。
5. 展示状态和发票流转记录。

### 解说词

> 项目成员发现票据信息有误时不能直接删除链上记录，而是提交作废申请。发行组织的开票员核对后决定批准或驳回。批准后原记录仍然保留，但状态变为已作废，不能再进入报销流程。这样既能纠正业务状态，又不会破坏审计历史。

### Org2 接收人的画面操作

## 五、剪辑建议

可以剪掉以下内容：

- 每次输入账号和密码的等待；
- 复制粘贴长文本的过程；
- Fabric 交易提交时的空白等待；
- 重复打开菜单和重复搜索的过程。

但不要剪掉以下关键状态变化：

- 项目从“待立项审核”变为“执行中”；
- 结项审核后出现可用额度；
- OCR 结果自动回填；
- 存证成功及账本中出现新发票；
- 报销审核后额度被冻结；
- 支付后冻结额度转为已支付；
- 作废申请经开票员批准后变为已作废；
- 接收方确认后责任人与组织发生变化；
- 审计页面可以展开 Fabric 交易编码。

建议在账号切换处添加 1 秒字幕，例如“项目管理审核员”“财务管理员”“Org2 外部协作方”，让观众立即理解当前角色。

## 六、出现意外时怎么处理

### 发票提示重复

说明保留的 OCR 发票已经被提前存证。不要在录屏中继续提交，改用另一张尚未上链的发票，或者重新准备数据后再录。

### 页面提示部分数据未刷新

点击当前页面右上角的刷新按钮。仍未恢复时使用 `Ctrl + Shift + R`，不要清空 Fabric 网络。

### 提示 8080 端口被占用

说明后端已经运行，不要再次启动，直接访问 `http://localhost:8080`。

### 审核员看不到刚提交的记录

先确认已经退出原账号并登录正确岗位，再点击页面右上角刷新。不要连续重复提交同一操作。

### OCR 暂时失败

保留错误画面不要继续录，检查网络和阿里云服务后重录这一小节。系统也支持手工录入，但正式演示优先展示 OCR。
