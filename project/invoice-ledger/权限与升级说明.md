# 作废、多组织身份与角色权限：升级和演示说明

本次升级实现三项高优先级能力：

1. **发票作废/红冲**：不删除原始存证，而是新增 `VOID` 链上交易，将状态改为 `VOIDED` 并保存原因。
2. **Org1 / Org2 真实 Fabric 身份**：后端会按照登录账户选择对应的测试证书、MSP、TLS 证书和 Peer。
3. **登录与角色权限**：不同角色只能看到和调用被允许的业务操作。

## 一、先升级已经部署的链码

你当前网络中已经有：

```text
invoice
Version: 1.0
Sequence: 1
```

因此不要再运行普通的 `deploy-chaincode.sh`。在 Fabric 网络仍运行时，执行：

```bash
cd /home/wenqin/bc/blockchain/project/invoice-ledger
./scripts/upgrade-chaincode.sh
```

该脚本会使用：

```text
Version: 1.1
Sequence: 2
```

Fabric 的链码升级必须递增 Sequence；这也是之前重复部署 `1.0 / Sequence 1` 报错的原因。

> 若你已经升级到 `1.1 / Sequence 2`，并在读取旧发票时看到 `voidReason is required`，请运行 `./scripts/upgrade-chaincode-v1.2.sh`。它会升级到 `1.2 / Sequence 3`，兼容旧发票中缺失的作废原因字段。

> 若你已经升级到 `1.2 / Sequence 3`，请运行 `./scripts/upgrade-chaincode-v1.3.sh` 升级到 `1.3 / Sequence 4`。该版本会在链码中校验“发票号码”全局唯一，不能再用不同发票 ID 重复存证同一个发票号码。

> 若你已经升级到 `1.3 / Sequence 4`，请运行 `./scripts/upgrade-chaincode-v1.4.sh` 升级到 `1.4 / Sequence 5`。该版本加入链上业务用户注册；创建发票或流转时，接收人必须是已注册、组织匹配且角色为流转员（`HOLDER`）的用户。

> 若你已经升级到 `1.4 / Sequence 5`，请运行 `./scripts/upgrade-chaincode-v1.5.sh` 升级到 `1.5 / Sequence 6`。该版本增加项目申请、立项/结项审核、资金池、报销审核和财务支付功能。

> 若你已经升级到 `1.5 / Sequence 6`，请运行 `./scripts/upgrade-chaincode-v1.6.sh` 升级到 `1.6 / Sequence 7`。该版本修复首次查询时空项目、空报销单和空项目事件响应导致的 JSON 解析错误。

升级成功后，停止旧的后端进程（运行 `start-app.sh` 的终端按 `Ctrl+C`），再重新启动：

```bash
./scripts/start-app.sh
```

刷新浏览器并重新登录。

## 二、三种演示账户

| 网页账户 | 默认密码 | 角色 | Fabric 技术身份 | 允许操作 |
| --- | --- | --- | --- | --- |
| `issuer-org1` | `issuer123` | 开票员 | `User1@org1.example.com` / `Org1MSP` | 查询、核验、创建存证、作废 |
| `holder-org2` | `holder123` | 流转专员 | `User1@org2.example.com` / `Org2MSP` | 查询、核验、流转自己组织持有的发票 |
| `auditor` | `auditor123` | 审计查看员 | `User1@org1.example.com` / `Org1MSP` | 查询、核验、查看历史 |

这些密码仅用于本地课程演示。生产系统应使用数据库账户、密码哈希、企业单点登录和由 CA 注册的独立用户证书。

## 三、项目与报销第一版（新增）

项目组成员先创建项目草稿并提交申请；项目管理审核员可通过或要求修改，且必须填写审核意见。立项通过后，申请预算会成为该项目的可用资金池。

关联项目创建的发票才能用于该项目报销。项目组成员提交报销单时，链码会校验发票确实关联该项目、未作废且尚未用于其他报销单。项目管理审核员通过报销时，金额从“可用余额”转为“冻结额度”；财务管理员确认支付后，冻结额度转为“已支付”，因此总额无法超过立项预算。

新增演示账户：

| 账户 | 密码 | 角色 |
| --- | --- | --- |
| `project-member` | `member123` | 项目组成员：申请项目、提交结项与报销 |
| `project-reviewer` | `review123` | 项目管理审核员：立项、结项、报销审核 |
| `finance-admin` | `finance123` | 财务管理员：确认支付 |

> 本版将资金池在“立项审核通过”时启用，以便项目执行期间即可采购和报销；结项审核通过并不自动清空余额，便于完成尚未支付的合规报销。

## 四、注册链上业务用户（新增）

登录弹窗中选择“没有业务账户？去注册”，填写登录账号、姓名/主体名称、所属组织、岗位和密码。注册成功后会发生两件事：

1. 后端使用所选组织的 Fabric 演示证书提交 `RegisterBusinessUser` 交易，把用户档案写入区块链；它包含账号、姓名、MSP、角色、状态和创建时间。
2. 登录密码只以加盐哈希形式保存在后端本机的 `backend/data/accounts.json`，用于下次网页登录；密码本身不会上链。

要演示完整流程，建议先注册一个 `Org2MSP` 的“流转员”，例如账号 `xiaoming`、姓名“小明”。随后创建发票时，把“购买方（链上接收人账号）”填为 `xiaoming` 并选择 `Org2MSP`。如果填写未注册账号、选错组织，或接收人不是流转员，链码会拒绝交易，且不会产生新记录。

同样，流转详情里的“下一持有人账号”只能填写已注册的流转员。输入一个不存在的账号时，错误提示会明确说明需先注册。

这里的“业务用户”与 Fabric 证书身份是两层概念：课程 Test Network 仍由每个组织的 `User1` 测试证书代表该组织签名；链上业务用户用于本项目中的主体、角色和流转校验。若要实现真正每人一张 Fabric 证书，需要增加 Fabric CA 的注册、登记和签发流程。

## 五、推荐演示流程

### 1. Org1 开票

使用 `issuer-org1 / issuer123` 登录，创建发票时将“购买方组织”选择为 `Org2MSP`。提交后，链码会记录：

```text
发行组织：Org1MSP
当前持有人组织：Org2MSP
```

交易由 Org1 的 `User1@org1` 测试证书签名。

### 2. Org2 流转

退出后使用 `holder-org2 / holder123` 登录。打开刚创建的发票详情，可以看到流转操作；将它转给下一持有人，并选择接收组织。

链码会根据调用者证书检查：

```text
调用者 MSP == 发票当前持有人组织 MSP
```

不满足时，交易会被拒绝。该交易由 Org2 的 `User1@org2` 证书签名。

### 3. Org1 作废

重新登录 `issuer-org1 / issuer123`，打开同一张发票，在“作废/红冲”填写原因。链码只允许发票发行组织作废，并会：

```text
保留原发票记录
新增一条 VOID 流转事件
将当前状态变为 VOIDED
保存作废原因
```

作废后，发票不能继续流转，但仍可查询、核验和查看完整历史。

### 4. 审计查看

登录 `auditor / auditor123` 后，可以查询、核验、查看流转和历史；创建、流转、作废接口均会返回 `403`，证明角色权限生效。

## 六、链上与后端分别保证什么

```text
后端登录角色：控制网页/API 允许哪些操作
Fabric 用户证书：决定交易由 Org1 还是 Org2 的真实测试身份签名
链码 MSP 校验：确保流转方属于当前持有人组织，作废方属于发行组织
```

这三层共同实现演示版的权限闭环。当前 Audit 账户复用 Org1 的测试证书，仅在后端实现只读权限；若要进一步生产化，应由 Fabric CA 为每位审计员注册独立身份，并在链码中读取证书属性实现角色校验。

## 七、关于旧发票

升级前已经创建的发票没有 `issuerMspId`、`holderMspId` 字段，因此仍可查询和核验，但不能使用新版的组织校验流转或作废功能。请新建一张发票演示新功能。
