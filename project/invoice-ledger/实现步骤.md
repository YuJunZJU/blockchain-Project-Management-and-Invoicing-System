# 链证发票系统实现、部署与验收步骤

## 1. 先完成环境准备

本项目使用项目内 `fabric-runtime/` 提供的 Fabric Test Network。开发机需要具备 Docker（含 Compose）、Git 与 Go 1.23+；`fabric-runtime/bin` 中包含运行网络所需的 Fabric 二进制文件。

在 Ubuntu 上先安装 Go，并确认版本：

```bash
go version
docker version
```

若 `fabric-samples/bin/peer` 不存在，需要按课程环境或 Fabric 官方安装脚本补齐 Fabric 二进制和 Docker 镜像。不要在已运行其他 Fabric 实验网络时直接执行本项目的启动脚本。

## 2. 启动 Fabric 网络

在 `project/invoice-ledger` 中执行：

```bash
./scripts/start-network.sh
```

脚本会启动双组织 Test Network 并创建 `mychannel`。它默认定位到项目内 `fabric-runtime/test-network`；如需改用其他网络，先指定：

```bash
export FABRIC_TEST_NETWORK=/绝对路径/fabric-samples/test-network
```

验收点：`docker ps` 中出现 orderer、peer0.org1、peer0.org2 等 Fabric 容器。

## 3. 部署智能合约

```bash
./scripts/deploy-chaincode.sh
```

该脚本以 `invoice` 为链码名、`1.0` 为版本将 `chaincode/` 部署到 `mychannel`。合约实现以下交易：

| 合约交易 | 作用 |
| --- | --- |
| `CreateInvoice` | 存证一张唯一发票并创建首次流转记录 |
| `ReadInvoice` / `GetAllInvoices` | 查询发票 |
| `TransferInvoice` | 校验当前持有人后执行流转 |
| `GetInvoiceFlows` | 查询不可变的流转链 |
| `VerifyInvoice` | 比对提交哈希和链上内容哈希 |
| `GetInvoiceHistory` | 查询 Fabric 键级历史 |

验收点：脚本输出链码提交成功；可使用 `network.sh cc list` 进一步检查已提交链码。

## 4. 启动 B/S 应用

另开终端运行：

```bash
./scripts/start-app.sh
```

脚本会启动 Gin 服务，静态前端由同一端口托管。访问 `http://localhost:8080`。

## 5. 按业务流程验收

1. 在“创建链上存证”填写发票号码、日期、销售方、购买方、金额和税额，提交。
2. 确认清单出现新记录，状态为“已开具”，并记录页面返回的 `dataHash`。
3. 点击该发票的“详情”，在“流转”中以当前持有人为操作人，填写下一持有人并提交。
4. 确认状态改为“流转中”，流转链中出现第二条记录；“链上历史”也出现新交易。
5. 在“发票核验”填写发票 ID 和正确 `dataHash`，应显示“内容完整、链上记录有效”。将哈希任意改动一位后再次核验，应显示“不匹配”。

## 6. 提交物准备

按老师的命名规范建立目录：`组号-组长_组员-姓名-链证发票管理系统`，并放入：

- 本项目完整源代码；
- 项目介绍文档（可基于 `项目介绍.md` 完善）；
- 答辩 PPT（按 `答辩材料大纲.md` 制作）；
- 7 分钟演示录屏；
- 组内分工及 10 分制贡献评分（按 `团队分工模板.md` 填写）。

## 7. 可迭代方向

答辩中可说明：生产环境应接入 CA 为每个企业签发证书，按组织和属性实施权限控制；PDF/OFD 原文件应保存到对象存储或 IPFS，链上仅保存文件哈希与访问索引；还可接入 OCR、税务接口和二维码扫码核验。
