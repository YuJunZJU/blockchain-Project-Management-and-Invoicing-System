# 链证项目管理与发票报销系统使用手册

本手册面向项目组成员和演示使用者。即使没有参与开发，也可以按本文完成环境启动、组织登记、注册、项目申请、发票存证、报销、作废申请和核验。系统运行在 Hyperledger Fabric 测试网络上；页面中标记为“已写入链上”的业务记录可追溯、不可直接修改或删除。

## 1. 使用前准备

### 1.1 你需要具备什么

- Ubuntu、WSL 或虚拟机环境；
- Docker 与 Docker Compose 已安装，并且当前用户可执行 `docker ps`；
- Go 已安装；
- 完整项目目录，以及项目内的 `fabric-runtime/` 运行环境目录。

> `fabric-runtime/` 中包含 Fabric 二进制、配置和 Test Network。它体积较大且含本地测试证书，因此不会上传到 GitHub。第一次在新电脑使用时，请从已能运行项目的同学电脑完整复制该目录到项目根目录。详细说明见 [fabric-runtime/README.md](fabric-runtime/README.md)。

OCR 是可选能力。未配置阿里云密钥时，系统仍可手动录入发票，不影响项目、报销和区块链功能。

### 1.2 第一次启动或已重置网络

系统管理员先在项目根目录启动服务：

```bash
cd /home/wenqin/bc/blockchain/project/invoice-ledger
./scripts/start-network.sh       # 第一次启动或网络未运行时执行
./scripts/deploy-chaincode.sh    # 第一次部署或网络重新创建后执行
./scripts/start-app.sh
```

浏览器访问：`http://localhost:8080`。

看到链码部署输出中的 `Chaincode definition committed` 后，再执行 `start-app.sh`。终端显示“链证发票服务已启动”即表示可打开浏览器。

### 1.3 日常启动、更新代码与链码升级

- 日常使用时，若 Fabric 网络和链码已运行，通常只需执行 `./scripts/start-app.sh`。
- 修改了前端页面后，浏览器按 `Ctrl + F5` 强制刷新；修改 Go 后端后，先在后端终端按 `Ctrl + C`，再重新执行 `./scripts/start-app.sh`。
- 从旧代码更新到本版、且当前链码为 v1.9 / Sequence 1 时，先执行：

```bash
./scripts/upgrade-chaincode-v2.0.sh
./scripts/start-app.sh
```

该升级会保留现有账本数据，并增加“项目组作废申请—开票员审核”能力。不要对已经部署过链码的网络重复执行 `deploy-chaincode.sh`。

若页面提示连接 `127.0.0.1:7051` 被拒绝，说明 Fabric 网络没有启动，应依次重新执行“第一次启动”中的前三条命令。

## 2. 页面与基本规则

登录后，可使用左侧边栏切换功能：

| 页面 | 用途 |
| --- | --- |
| 工作概览 | 查看发票数量、流转中数量、总金额和当前登录身份。 |
| 组织管理 | 登记主体组织、内部项目组和外部协作组织；点击组织可查看其链上成员。 |
| 项目管理 | 项目申请、立项审核、结项审核和资金池查看。 |
| 发票存证 | OCR 识别或手工录入发票，并将其存证到链上。 |
| 发票账本 | 搜索发票、查看详情、流转轨迹、作废记录和历史。 |
| 报销支付 | 用项目中的已存证发票创建报销单、审核及确认支付。 |
| 发票核验 | 用发票 ID 和内容指纹验证展示内容是否与链上记录一致。 |

系统会自动生成项目 ID、报销单 ID 等内部编号，普通使用者无需填写或记忆。发票 ID 也会自动生成；发票号码仍应填写真实、唯一的发票号码。

> 注意：页面上的“作废”不会删除链上数据，而是新增一条作废交易。因此，已作废发票仍可在账本和历史中查询，但不能用于报销。

## 3. 注册、登录与岗位

### 3.1 新用户注册

1. 在登录窗口点击“没有业务账户？去注册”。
2. 填写登录账号、姓名或主体名称，从下拉框选择已登记的业务组织、岗位和密码。
3. 登录账号只能使用 3–32 位英文、数字、下划线或连字符；密码至少 6 位。
4. 点击“注册并写入区块链”。

注册成功后：姓名、账号、所属业务组织、底层 Fabric 接入节点和岗位会写入 Fabric 成员名录；密码只以哈希形式保存在本机的 `backend/data/accounts.json`，不会写到区块链上。

本课程测试网络中，系统按所选组织使用其代表性的 Fabric 测试证书提交交易；“注册业务用户”创建的是系统内的链上业务档案，并不等同于为每位用户单独签发新的 X.509 证书。

### 3.2 内置演示账户

以下账户可直接用于登录演示。若网络刚被完全清空，建议另外注册自己的测试账号，使其出现在链上成员名录中。

| 账号 | 密码 | 岗位 |
| --- | --- | --- |
| `project-member` | `member123` | 项目组成员 |
| `project-reviewer` | `review123` | 项目管理审核员 |
| `finance-admin` | `finance123` | 财务管理员 |
| `org-admin` | `orgadmin123` | 组织管理员 |
| `issuer-org1` | `issuer123` | 开票员 |
| `holder-org2` | `holder123` | 跨组织流转员 |
| `auditor` | `auditor123` | 审计员 |

### 3.3 各岗位可以做什么

| 岗位 | 主要操作 |
| --- | --- |
| 项目组成员 | 创建、修改和提交项目；申请结项；存证关联本项目的发票；提交报销单；申请作废本人项目关联的发票。 |
| 项目管理审核员 | 审核项目立项、结项和报销单，并填写审核意见。 |
| 财务管理员 | 对已审核并冻结额度的报销单确认支付。 |
| 开票员 | 创建发票、创建项目、提交报销；可直接作废本组织开具的发票，并审核项目组的作废申请。 |
| 跨组织流转员 | 在确有组织间交接需要时接收或继续流转发票。 |
| 审计员 | 查询成员、项目、发票、流转历史和核验结果。 |

页面会按岗位隐藏无权限的按钮；即使通过接口直接请求，后端和链码也会再次校验权限。

### 3.4 登记业务组织

“组织管理员”可在“组织管理”页面登记三类业务组织：主体组织（学校/总部）、公司内部项目组、外部协作组织（财务或合作单位）。内部项目组必须选择一个已登记的主体组织作为上级组织。

第一次使用可按以下顺序操作：

1. 使用内置账号 `org-admin / orgadmin123` 登录。
2. 登记一个“主体组织”，例如“某某大学”或“公司总部”。
3. 登记“内部项目组”时，选择刚创建的主体组织作为上级组织。
4. 如需模拟外部财务或合作方，再登记“外部协作组织”。
5. 其他成员注册时选择对应的业务组织和岗位。

这里登记的是业务组织档案，会写入 Fabric 账本；它不会自动创建新的 Fabric Peer、MSP 或区块链证书。当前课程网络底层仍使用 Org1MSP 与 Org2MSP 两个技术节点。详细区别见 [组织管理说明.md](组织管理说明.md)。

## 4. 推荐的完整业务流程

推荐按以下顺序演示或日常使用：

```text
项目组成员创建项目
  → 提交立项申请
  → 项目管理审核员通过
  → 项目进入执行中并获得可用资金池额度
  → 项目组成员存证关联项目的发票
  → 提交报销单
  → 审核员通过并冻结相应额度
  → 财务管理员确认支付
  → 资金池的已支付金额增加
```

需要结项时，项目组成员提交结项材料说明，项目管理审核员在项目详情中完成结项审核。项目处于“执行中”或“结项审核通过”时，均可按系统规则发起报销。

## 5. 项目管理

### 5.1 创建并提交项目

1. 使用“项目组成员”或“开票员”账号登录，进入“项目管理”。
2. 填写项目名称、项目内容、预期结项日期和申请预算，点击“保存项目草稿”。
3. 在项目列表找到该项目，点击“提交”。
4. 项目状态变为“待立项审核”。

草稿或被要求修改的项目可以由原申请人编辑后再次提交。项目 ID 由系统自动生成，不需要手工填写。

### 5.2 审核立项和结项

1. 使用“项目管理审核员”登录。
2. 在待审核项目所在行点击“立项审核”，或点击“详情”后在详情底部操作。
3. 填写具体审核意见，选择“通过立项”或“要求修改”。
4. 通过后项目进入“执行中”，预算成为项目资金池的可用额度。

项目组成员在项目“执行中”时可点击“申请结项”，填写结项报告、成果材料或链接说明。审核员按同样方式进行结项审核。

### 5.3 查看资金池

项目列表和详情会显示三项金额：

- 可用余额：尚未被报销审核占用的额度；
- 冻结额度：报销已审核通过、等待财务支付的额度；
- 已支付：财务已确认支付的总额。

系统不允许审核通过后使“可用余额”小于零。

## 6. 发票存证与 OCR

### 6.1 使用 OCR 识别

1. 进入“发票存证”。
2. 点击“选择发票文件”，或直接将图片/PDF 拖入虚线区域。
3. 点击“开始识别”。识别成功后会回填发票号码、日期、销售方、购买方和金额等字段。
4. 人工检查和补全所有字段后，再点击“生成存证并上链”。

OCR 仅用于辅助录入；识别结果不会自动上链。请特别核对金额、税额、日期、发票号码和关联项目。若未配置阿里云 OCR，仍可完全手工填写发票信息。

### 6.2 手工存证

填写发票号码、开票日期、销售方、购买方、金额、税额、币种，必要时从“关联项目”选择执行中的项目。提交后系统会自动：

1. 生成发票 ID；
2. 根据稳定的发票字段计算 SHA-256 内容指纹；
3. 将发票、指纹、当前责任人及首次存证记录写入 Fabric。

相同发票 ID 或相同发票号码不能重复存证。存证成功后可到“发票账本”查看。

### 6.3 发票详情、作废与跨组织流转

在“发票账本”中，可按发票 ID、发票号码、销售方、购买方或当前责任人搜索。点击“详情”可查看：发票字段、内容指纹、流转轨迹和链上历史。

- **直接作废/红冲**：开票员只能直接作废本组织开具、且未作废的发票。必须填写原因；作废后不可恢复为可报销状态。
- **跨组织流转**：这是可选操作，普通项目报销不需要它。只有当前责任人可将发票交接给已注册、岗位为“跨组织流转员”的成员。输入账号、姓名或组织后，从候选成员中点击选择，系统会自动匹配其所属节点。

### 6.4 项目组申请作废

适用场景：项目成员发现已关联本人项目的发票录入有误、需要重新开具，但没有直接作废权限。

1. 使用该项目的申请人（项目组成员）登录，在“发票账本”打开目标发票的“详情”。
2. 在“项目组作废申请”区域填写具体原因，点击“提交作废申请”。
3. 此时发票**不会立即作废**，状态为等待开票员审核；申请记录已写入链上。
4. 使用该发票发行组织的“开票员”登录，打开同一张发票详情。
5. 查看申请人、原因和时间，填写审核意见，选择“批准并正式作废”或“驳回申请”。
6. 批准后，发票状态变为“已作废”，无法再用于报销；驳回后发票保持有效，项目成员可补充原因并再次提交。

发票详情的“发票流转”会按时间显示开具、提交申请、驳回和最终作废等链上记录。

## 7. 报销与支付

### 7.1 提交报销单

1. 使用项目申请人（项目组成员或开票员）登录，进入“报销支付”。
2. 先选择执行中的关联项目。
3. 系统只会列出该项目下、未作废且尚未用于报销的发票；选择一张发票。
4. 填写材料说明，例如支付凭证、采购用途或附件位置。
5. 点击“提交报销审核”。

报销单 ID 会自动生成。金额取自所选发票，不能在报销单中任意修改。

### 7.2 审核与支付

1. 项目管理审核员登录，在待审核报销单右侧点击“审核”。
2. 选择通过或要求修改，并填写审核意见。
3. 审核通过后，报销单状态变为“已审核，额度已冻结”。
4. 财务管理员登录，对该报销单点击“确认支付”。
5. 支付确认后状态变为“已支付”，冻结额度转入已支付金额。

## 8. 发票核验

核验用于证明当前展示的发票内容是否对应链上存证。

1. 在“发票账本”打开目标发票的“详情”。
2. 点击“填入核验中心”，系统会自动带入发票 ID 和内容指纹。
3. 在“发票核验”页面点击“立即核验”。

显示“核验通过”代表输入的内容指纹与该发票链上记录一致。若将任何内容重新计算成不同指纹，或输入错误 ID/指纹，系统会提示核验失败。

## 9. 常见问题

### 页面提示未登录或登录后没有权限

先确认账号密码是否正确，再查看左下角显示的姓名、组织和岗位。需要其他操作时，请退出并登录对应岗位的账号；不要尝试借用他人的密码。

### 提示“连接被拒绝”或“区块链交易未提交”

通常是 Fabric 网络未运行、链码未部署或刚重启尚未就绪。由管理员检查 Docker，再依次执行 `./scripts/start-network.sh`、`./scripts/deploy-chaincode.sh` 和 `./scripts/start-app.sh`。已存在网络时不要反复部署同一序列号链码。

### 发票或项目没有出现在下拉框

点击相应页面右上角“刷新”。报销区只显示“当前项目关联、未作废、未被其他报销单使用”的发票；项目下拉框只显示可报销状态的项目。

### 看不到“项目组作废申请”或提交后提示接口不存在

确认已升级到本版链码并重启后端。对于 v1.9 / Sequence 1 的旧网络，在项目根目录执行：

```bash
./scripts/upgrade-chaincode-v2.0.sh
./scripts/start-app.sh
```

此外，项目组成员只能对“自己申请的项目”关联发票提出申请；未关联项目的发票只能由开票员直接作废。

### OCR 识别失败

确认文件为清晰的图片或 PDF、文件大小未超过限制，并检查管理员是否已在项目 `.env` 中配置阿里云 OCR 的 AccessKey。OCR 输出只能作为录入建议，应以原始发票为准。

### 重启后自己注册的账号无法登录

检查 `backend/data/accounts.json` 是否被删除或替换。该文件保存本机的密码哈希；删除它会清除本机登录凭据，但不会自动删除链上的业务用户档案。测试环境若需要完全重置，应由管理员统一清空网络并重新注册。

## 10. 安全提示

- 不要把 `.env`、阿里云 AccessKey、密码或 `backend/data/accounts.json` 提交到 GitHub。
- 不要为了“重新测试”直接删除单条链上发票；应使用作废功能，保留可审计记录。
- 项目成员提交的作废申请并不会立即删除或作废发票，必须由开票员审核后才会改变发票状态。
- 课程测试网络仅用于开发演示，不能直接作为生产财务系统使用。
