# 项目、资金池与报销模块说明

本模块在原有发票存证、链上用户和核验功能基础上，增加项目申请、固定审核流程、资金池与报销支付控制。

## 一、固定业务流程

```text
项目草稿
→ 提交立项审核
→ 需修改 / 执行中（立项通过）
→ 提交结项申请
→ 结项材料需修改 / 结项验收通过

执行中或结项验收通过的项目
→ 关联项目创建发票
→ 创建报销单
→ 报销审核通过，冻结额度
→ 财务确认支付，计入已支付金额
```

项目组成员只能编辑自己的草稿或被要求修改的项目；项目管理审核员负责立项、结项和报销审核；财务管理员只负责确认实际支付。

## 二、资金池规则

立项审核通过时，申请预算成为项目资金池的可用额度。

```text
可用余额 = 立项预算 - 冻结额度 - 已支付金额
```

报销审核通过后，金额从“可用余额”转为“冻结额度”。财务确认支付后，金额从“冻结额度”转为“已支付金额”。因此多个报销单并发审核时，Fabric 会对同一项目状态执行并发一致性校验，超预算的交易不能提交。

同一张发票只能创建一张报销单；作废发票不能报销；发票必须在创建时关联对应项目。

## 三、演示账户

| 账户 | 密码 | 角色 | 可执行动作 |
| --- | --- | --- | --- |
| `project-member` | `member123` | 项目组成员 | 创建/修改/提交项目，申请结项，创建报销单，创建项目关联发票 |
| `project-reviewer` | `review123` | 项目管理审核员 | 审核立项、结项和报销单，必须填写意见 |
| `finance-admin` | `finance123` | 财务管理员 | 对已冻结额度的报销单确认支付 |
| `auditor` | `auditor123` | 审计查看员 | 查看账本、项目、报销单和链上事件 |

原有 `issuer-org1`、`holder-org2` 账户仍用于发票演示。创建新发票时，购买方账号仍必须是一个已注册的 `HOLDER` 链上业务用户。

## 四、推荐演示步骤

1. 如尚未存在接收发票的链上流转员，点击“注册”，注册一个 `Org2MSP`、角色为“流转员”的账号，例如 `xiaoming`。
2. 使用 `project-member / member123` 登录，在“项目申请与资金池”创建草稿，再点击项目列表中的“提交”。
3. 退出后使用 `project-reviewer / review123` 登录，对待审核项目点击“立项审核”，选择通过并填写意见。项目状态成为“执行中”，可用余额等于批准预算。
4. 使用 `project-member` 登录，在“创建链上存证”中选择该项目，购买方填写 `xiaoming`、组织选择 `Org2MSP`，创建发票。
5. 在“报销单与支付”中选择该项目，填写刚创建的发票 ID 与材料说明，提交报销审核。
6. 使用 `project-reviewer` 登录，审核通过该报销单。项目列表中的可用余额减少，冻结额度增加。
7. 使用 `finance-admin / finance123` 登录，点击“确认支付”。冻结额度减少，已支付金额增加。
8. 项目完成后，使用 `project-member` 点击“申请结项”；项目管理审核员审核通过后，状态变为“结项验收通过”。

## 五、哪些数据上链

上链：项目状态、预算金额、资金池变化、发票/报销单关联、材料说明哈希、审核意见、操作者、时间与交易 ID。

不上链：原始申请书 PDF、结项报告、支付截图、行程单、发票图片。当前第一版会将“结项材料说明”和“报销材料说明”计算 SHA-256 后上链；后续接入 OCR 和附件上传时，应将真实文件放在本地文件系统或对象存储，再记录其文件哈希。
