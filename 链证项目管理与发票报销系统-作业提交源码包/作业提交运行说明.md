# 链证项目管理与发票报销系统：作业提交运行说明

> 本文件随课程源码包一并提供。该源码包已包含当前演示链上数据、预置账号、Fabric 运行环境和 OCR 配置，适合在 Ubuntu、WSL2 Ubuntu 或 Linux 虚拟机中恢复演示。仅供课程教学使用，不应用于真实财务业务。

## 1. 包内包含什么

```text
invoice-ledger/
├── backend/                     Go + Gin 后端；data/accounts.json 是预置本地账户
├── chaincode/                   Fabric 智能合约源码
├── web/                         前端页面
├── fabric-runtime/              Fabric 二进制、证书、通道配置和测试网络
├── ledger-state/                当前链上世界状态的 Docker 卷备份
├── scripts/                     网络、应用、账本恢复和检查脚本
├── .env                         OCR 配置（仅限本课程演示使用）
└── 作业提交运行说明.md          本说明
```

`ledger-state/` 中保存了当前演示用的组织、成员、项目、发票、流转和报销数据。Fabric 的世界状态实际保存在 Docker 卷中，因此只复制源码不足以保留演示数据；必须先执行第 3 节的恢复步骤。

## 2. 运行环境

推荐 Ubuntu 22.04/24.04、WSL2 Ubuntu 或 Linux 虚拟机，至少准备：

- Docker Engine 与 Docker Compose 插件；
- Go 1.23 或更高版本；
- 浏览器；
- 首次启动时可访问 Docker Hub 和 Go 模块下载源的网络。

在项目根目录检查环境：

```bash
cd /你的路径/invoice-ledger
chmod +x scripts/*.sh
chmod +x fabric-runtime/bin/*
chmod +x fabric-runtime/test-network/network.sh fabric-runtime/test-network/scripts/*.sh
./scripts/start-network.sh check
go version
```

若 `docker ps` 报权限不足，可执行下列命令后退出终端并重新登录：

```bash
sudo usermod -aG docker $USER
```

## 3. 恢复预置演示数据（推荐）

此方式会恢复提交时的链上数据，用于直接演示完整流程。

**前提：请在一套新的 Docker 测试环境中执行。** 恢复脚本只允许写入空 Docker 卷，发现已有账本数据时会主动停止，以免覆盖已有记录。

```bash
cd /你的路径/invoice-ledger
./scripts/verify-submission-package.sh
./scripts/restore-chain-state.sh
./scripts/start-network.sh resume
./scripts/start-app.sh
```

看到 `链证发票服务已启动：http://localhost:8080` 后，在浏览器访问：<http://localhost:8080>。

打开另一个终端可检查服务状态：

```bash
curl http://localhost:8080/health
```

预期响应中包含：`"status":"ok"` 与 `"fabric":"reachable"`。

## 4. 日常重启

电脑重启后，不要重复初始化和部署链码。依次执行：

```bash
cd /你的路径/invoice-ledger
./scripts/start-network.sh resume
./scripts/start-app.sh
```

如果提示 `listen tcp 0.0.0.0:8080: bind: address already in use`，说明已有后端服务正在运行；回到旧终端按 `Ctrl + C`，再启动一次即可。

## 5. 从零开始部署（不会保留预置数据）

仅在希望获得一套**空白**测试网络时使用下面流程。不要在已恢复演示数据后执行。

```bash
./scripts/start-network.sh init
./scripts/deploy-chaincode.sh
./scripts/start-app.sh
```

`init` 创建 Fabric 网络与 `mychannel` 通道；`deploy-chaincode.sh` 首次部署 `invoice` v2.6 链码。后续重启只使用 `resume`。

## 6. OCR 配置说明

提交包内 `.env` 已包含课程演示使用的阿里云 OCR 配置，启动应用时会自动读取。请不要把 `.env` 提交到公开 Git 仓库、截图展示或用于课程以外的用途。

OCR 是“上传/拖拽发票文件 → 自动识别字段 → 人工核对 → 用户点击存证上链”的辅助能力。OCR 失败时仍可手工填写发票并完成存证。

## 7. 推荐演示流程

1. 用 `org-admin` 查看业务组织及其成员；
2. 用 `alice` 或 `bob` 查看项目、发票存证和报销申请；
3. 用 `project-reviewer` 展示审核意见与报销通过后的冻结额度；
4. 用 `finance-admin` 展示支付状态和资金池变化；
5. 用 `holder-org2` 展示跨组织待确认/已交接票据；
6. 用 `auditor` 查看发票详情中的流转轨迹、业务交易记录和内容核验；
7. 打开“数据统计”展示预算、已批准额度、冻结额度、实际支付和趋势图。

## 8. 常见问题

| 现象 | 处理 |
| --- | --- |
| `permission denied while trying to connect to Docker daemon` | 执行 `sudo usermod -aG docker $USER` 后重新登录，再运行 `docker ps`。 |
| `connection refused 127.0.0.1:7051` | Fabric 网络未启动，执行 `./scripts/start-network.sh resume`。 |
| `address already in use :8080` | 已有后端占用端口，到旧终端按 `Ctrl + C` 后再启动。 |
| 页面旧样式或按钮无响应 | 浏览器按 `Ctrl + Shift + R` 强制刷新。 |
| 账本恢复脚本提示卷已有数据 | 这是防覆盖保护。请在新的 Docker 环境中恢复，不要强行覆盖已有课程演示账本。 |
| OCR 识别失败 | 检查网络和 `.env`；也可以直接手工录入。 |

## 9. 停止方式

运行应用的终端中按 `Ctrl + C` 可停止 Web 后端，链上数据不会丢失。Fabric 网络保留运行或随 Docker 重启后通过 `resume` 恢复均可。
