# 链证项目管理与发票报销系统：组员部署与快速上手手册

> 适用对象：拿到项目代码、但未参与开发的组员。按本文操作可在自己的 Ubuntu、WSL2 Ubuntu 或 Linux 虚拟机中独立运行系统。本文面向课程演示环境，不应用于真实财务业务。

## 先看结论

第一次运行只需要依次执行四步：检查环境、创建 Fabric 网络、部署链码、启动应用。

```bash
cd /你的路径/invoice-ledger
./scripts/start-network.sh check
./scripts/start-network.sh init
./scripts/deploy-chaincode.sh
./scripts/start-app.sh
```

最后在浏览器打开：<http://localhost:8080>。

`init` 和 `deploy-chaincode.sh` 只用于**第一次**部署。以后电脑重启，只需执行：

```bash
./scripts/start-network.sh resume
./scripts/start-app.sh
```

## 1. 你需要从组长处拿到什么

请确认拿到以下两部分。只克隆 GitHub 仓库通常还不够。

```text
invoice-ledger/
├── backend/                 后端服务
├── chaincode/               Fabric 智能合约
├── web/                     浏览器页面
├── scripts/                 启动与部署脚本
├── fabric-runtime/          必须单独复制的 Fabric 本地运行环境
│   ├── bin/
│   ├── config/
│   └── test-network/
└── .env.example
```

其中 `fabric-runtime/` 含 Fabric 命令行程序和测试网络配置，体积较大，按 Git 忽略规则不会上传到 GitHub。请让组长提供一个**未初始化的运行环境模板**，放到项目根目录下。

> 不要把已经运行过的 `fabric-runtime/test-network` 原样复制后再执行 `init`。其中的 `organizations/`、`channel-artifacts/` 可能保留旧证书和旧通道文件，而新电脑的 Docker 没有对应账本，会造成“检测到已有 mychannel”或证书/节点不匹配。

组长可以在项目根目录用下面命令制作一个不含旧账本材料的模板压缩包；它只读取文件，不会删除原电脑的任何数据：

```bash
tar -czf fabric-runtime-template.tar.gz \
  --exclude='fabric-runtime/test-network/organizations/peerOrganizations' \
  --exclude='fabric-runtime/test-network/organizations/ordererOrganizations' \
  --exclude='fabric-runtime/test-network/channel-artifacts' \
  --exclude='fabric-runtime/test-network/system-genesis-block/*.block' \
  --exclude='fabric-runtime/test-network/*.tar.gz' \
  fabric-runtime
```

组员拿到后，在项目根目录解压：

```bash
tar -xzf fabric-runtime-template.tar.gz
```

解压后应满足下面的路径存在，并且第一次部署前不应存在 `fabric-runtime/test-network/channel-artifacts/mychannel.block`：

```bash
test -f fabric-runtime/test-network/network.sh && echo "Fabric 运行环境已就位"
```

不要把组长电脑里的 `.env` 或 `backend/data/accounts.json` 原样发给其他人：前者可能包含 OCR 密钥，后者是该电脑上的本地登录账户。新电脑默认用内置演示账号即可；需要 OCR 时再由使用者自己配置 `.env`。

## 2. 新电脑环境准备

### 2.1 推荐系统

- Ubuntu 22.04/24.04、WSL2 Ubuntu，或 Linux 虚拟机；
- Docker Engine 与 Docker Compose 插件；
- Go **1.23 或更高版本**；
- 能访问 Docker Hub 与 Go 模块下载源的网络（首次部署需要拉取镜像/依赖）。

Windows 用户请在 WSL2 的 Ubuntu 终端内运行，项目目录建议放在 Linux 家目录中，例如 `~/blockchain/invoice-ledger`，不要直接在 Windows 的 `C:` 盘目录中运行。

### 2.2 安装并检查 Docker

若电脑还没有 Docker，可在 Ubuntu 中执行：

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-plugin
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
```

执行最后一行后，**退出当前终端并重新登录**（或重启 WSL），再检查：

```bash
docker --version
docker compose version
docker ps
```

若 `docker ps` 提示 `permission denied`，通常是还没有重新登录；临时可使用 `sudo docker ps` 检查，但项目运行建议完成上面的用户组配置。

### 2.3 安装并检查 Go

请从 Go 官方下载页安装 Linux 版 Go 1.23+，完成后重新打开终端并检查：

```bash
go version
```

版本低于 1.23 时不要继续部署。项目的后端和链码均使用 Go 1.23 的模块配置。

### 2.4 准备项目配置

在项目根目录执行：

```bash
cp .env.example .env
chmod +x scripts/*.sh
chmod +x fabric-runtime/bin/*
chmod +x fabric-runtime/test-network/network.sh fabric-runtime/test-network/scripts/*.sh
```

`.env` 初始可以保持为空，系统仍能手工录入发票。阿里云 OCR 与 AI 纠偏均为可选功能，见第 7 节。

## 3. 首次独立部署

以下命令必须在项目根目录运行：

```bash
cd /你的路径/invoice-ledger
./scripts/start-network.sh check
```

看到“环境检查通过”后，继续：

```bash
./scripts/start-network.sh init
./scripts/deploy-chaincode.sh
./scripts/start-app.sh
```

说明：

1. `init`：创建两个 Fabric 组织（Org1、Org2）、节点和业务通道 `mychannel`。
2. `deploy-chaincode.sh`：把本项目的 `chaincode/` 智能合约部署为 `invoice` 链码。这一步通常最久，首次拉镜像需要几分钟。
3. `start-app.sh`：启动 Go 后端与前端静态页面。终端保持运行；看到 `链证发票服务已启动：http://localhost:8080` 后访问浏览器。

若浏览器打不开页面，先在另一个终端检查：

```bash
curl http://localhost:8080/health
```

返回 `"status":"ok"` 表示后端与 Fabric 都可访问。

### 不要重复做的事

- 已经成功初始化过网络时，不要再执行 `./scripts/start-network.sh init`；应使用 `resume`。
- 已经部署过链码时，不要重复执行 `./scripts/deploy-chaincode.sh`；重复部署会报链码定义/Sequence 相关错误。
- 不要随意执行 `fabric-runtime/test-network/network.sh down` 或删除 `fabric-runtime/test-network/organizations`、`channel-artifacts`。这些操作可能使测试网络和账本状态无法恢复。

## 4. 日常启动、停止与更新

### 4.1 电脑重启后的正确启动方式

```bash
cd /你的路径/invoice-ledger
./scripts/start-network.sh resume
./scripts/start-app.sh
```

`resume` 只恢复现有容器，不会重新创建通道，也不会清空已有项目、发票和报销单。

### 4.2 停止应用

在运行 `./scripts/start-app.sh` 的终端按 `Ctrl + C` 即可停止网页/后端服务。Fabric 网络可以继续运行，数据不会丢失。

如果再次启动时报：`listen tcp 0.0.0.0:8080: bind: address already in use`，说明已有一个应用服务正在使用 8080；回到原来运行应用的终端按 `Ctrl + C`，不要同时启动两个 `start-app.sh`。

### 4.3 拉到新前端或后端代码

- 仅前端改动：刷新浏览器并按 `Ctrl + Shift + R`。
- 后端 Go 代码改动：停止旧 `start-app.sh` 后重新运行它。
- 链码改动：必须由维护者明确提供新的升级脚本和版本/Sequence；**不要自行猜测或重复运行旧升级脚本**。链码升级应保留账本数据，但参数错了会失败。

## 5. 第一次演示：推荐测试顺序

新网络没有任何业务数据。推荐按此流程建立一套完整演示数据。

### 5.1 可直接登录的内置演示账号

| 账号 | 密码 | 主要用途 |
| --- | --- | --- |
| `org-admin` | `orgadmin123` | 在 Org1 登记业务组织 |
| `org-admin-org2` | `orgadmin234` | 在 Org2 登记外部组织 |
| `project-member` | `member123` | 创建项目、存证、提交报销 |
| `project-reviewer` | `review123` | 立项、结项、报销审核 |
| `finance-admin` | `finance123` | 确认支付 |
| `issuer-org1` | `issuer123` | 开票与直接作废发票 |
| `holder-org2` | `holder123` | 接收跨组织交接的发票 |
| `auditor` | `auditor123` | 审计查看与核验 |

### 5.2 建议的完整操作

1. 用 `org-admin` 登录，进入“组织管理”，登记一个“牵头单位”，例如“某某大学”。
2. 仍用 `org-admin`，登记一个“内部项目组”，上级选择刚才的牵头单位。
3. 退出并注册一个成员账号，例如 `alice`，所属组织选择这个项目组。注册后的默认岗位是“项目组成员”。
4. 用 `alice` 登录，在“项目管理”填写项目名称、内容、预算、预计结项时间，先保存草稿，再提交立项申请。
5. 用 `project-reviewer` 登录，打开项目详情，填写意见并通过立项。项目进入“执行中（未拨款）”。
6. 用 `alice` 登录，项目完成后在项目详情申请结项，填写结项材料说明。
7. 用 `project-reviewer` 登录，通过结项审核。项目进入“财务结算中”，预算变为可用额度。
8. 用 `alice` 登录，在“发票存证”上传 OCR 文件或手工填写发票。关联刚才的项目，提交存证。
9. 进入“报销支付”，选择该项目和该发票，填写材料说明，提交报销单。
10. 用 `project-reviewer` 审核报销单并通过；系统冻结对应项目额度。
11. 用 `finance-admin` 确认支付；项目资金池的已支付金额增加。
12. 所有报销处理完后，用 `finance-admin` 在项目详情中完成结算归档；未使用的可用额度会被回收。

## 6. 业务规则：为什么有些按钮不可用

### 6.1 项目与资金池

```text
草稿 → 待立项审核 → 执行中（未拨款）
     → 待结项审核 → 财务结算中（有可用额度）
     → 已结算归档
```

- 立项审核通过只代表项目可以执行，**不会立即产生报销额度**。
- 结项审核通过后，项目预算进入资金池，才可以提交报销。
- 报销审核通过：额度从“可用”变为“冻结”。
- 财务确认支付：冻结额度变为“已支付”。
- 归档前必须没有待审核/待修改/已冻结的报销单；归档后不能再存证关联该项目或新增报销。

### 6.2 发票

- 发票 ID 可留空，系统自动生成；发票号码必须按票面填写且不能与有效存证重复。
- 发票一旦上链不能直接删除。录入错误时可作废原记录并创建更正版本，原始历史仍保留。
- 发票关联项目后，可在详情中取消关联；但已经关联报销单、已作废或项目已归档时不能取消。
- 一张有效发票只能关联一张未撤回/已审核/已支付的报销单；撤回未支付报销单后，该发票可再次选择。

### 6.3 可选的跨组织材料交接

这不是固定报销流程，只有纸质票据或材料确实需要交给其他组织保管时才使用：

```text
当前责任人发起交接 → 填写说明 → 接收人确认/拒绝
```

只有接收人确认后，发票当前责任人才改变。`holder-org2` 可用来演示接收 Org2 的交接票据。

### 6.4 谁能看到哪些数据

- 普通注册成员：查看自己所属业务组织及其项目范围内的数据。
- `project-member`、`issuer-org1`：查看 Org1 范围内与项目/开票相关的数据。
- `holder-org2`：只查看当前已交接到 Org2 的发票。
- 审核员、财务管理员、审计员、组织管理员：可查看全局账本，以完成审核、支付、审计与管理任务。

## 7. OCR（可选）

没有 OCR 配置时，发票页面仍可以手动填写并上链。

若要启用阿里云 OCR，在项目根目录编辑 `.env`，填写自己的 RAM AccessKey：

```ini
ALIYUN_ACCESS_KEY_ID=你的AccessKeyID
ALIYUN_ACCESS_KEY_SECRET=你的AccessKeySecret
ALIYUN_OCR_REGION=cn-hangzhou
```

保存后重启 `./scripts/start-app.sh`。`.env` 包含密钥，不能提交 GitHub、不能截图发送、也不要放入课程报告。

## 8. 常见问题排查

| 现象 | 原因与处理 |
| --- | --- |
| `permission denied while trying to connect to Docker daemon` | Docker 用户组配置未生效。执行 `sudo usermod -aG docker $USER` 后重新登录。 |
| `Peer binary and configuration files not found` | `fabric-runtime/` 未完整复制，或 `bin/*` 没有执行权限。检查第 1、2.4 节。 |
| `connection refused 127.0.0.1:7051` | Fabric 网络未恢复。执行 `./scripts/start-network.sh resume`。 |
| `address already in use :8080` | 已有后端正在运行。到旧终端按 `Ctrl + C`，再启动一次。 |
| 页面旧样式、按钮没反应 | 浏览器按 `Ctrl + Shift + R` 强制刷新。 |
| `attempted to redefine the current committed sequence` | 重复部署/升级链码。不要再执行部署脚本，先向维护者确认当前链码版本。 |
| 注册后登录失败 | 确认登录的是**同一台电脑、同一个项目目录**。本地账户保存在 `backend/data/accounts.json`，不会自动同步到别的电脑。 |
| OCR 识别失败 | 检查 `.env`、阿里云 OCR 服务权限、网络；也可直接手工录入。 |
| 发票不能关联项目 | 登录用户与目标项目不属于同一业务组织，或项目已归档；可取消关联或使用正确组织成员登录。 |

## 10. 给组员的一句话说明

本系统把项目、发票、报销和审批的关键状态写入 Hyperledger Fabric 账本。页面负责录入和展示；后端负责登录、权限、OCR 和调用 Fabric；链码负责校验“谁能操作、项目额度是否足够、发票是否可报销”等规则。链上记录不能直接删除，错误通过作废、更正、撤回和审核意见等新交易来保留处理轨迹。
